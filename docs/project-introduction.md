# Hope Archive 项目介绍

> 面向新组员与老师，预计阅读 2–4 分钟。更新日期：2026-09-06。本文描述计划，当前仓库为初始化骨架。

## 30 秒介绍（Pitch）

Hope Archive 是一个本地优先（Local-first）的个人日记归档软件项目：将用户有权提供的日记、日期和图片保存到自己的设备，方便浏览、查找，再导出成可迁移的数据包和适合长期重读的日志。第一版完成这条完整流程，AI 搜索和回顾作为可选增强。项目名称暂定，不代表 Hope 官方产品或认可。

## 我们要解决什么问题（Problem）

发起者在 Hope 已积累约八万字日记，这是个人估算。目前的真实痛点是尚未找到满意的批量导出方式，已有导出尝试在结构和排版上也不够理想。这里反映个人体验，Hope 当前完整导出能力仍待验证。

用户需要的不只是拿到一份文本：正文、日期和图片要能对应；离开平台或断网后还能够阅读；想找回一段经历时，不必从头翻找。普通用户也不希望为了保存日记先配置开发工具或智能体（Agent）。

## 我们准备怎样解决（Solution）

围绕“导入 → 本地保存 → 浏览与搜索 → 导出”建立一条可独立使用的流程。导入处理本人授权数据或用户自有文件，保存原始内容与图片关系，让用户知道成功保存了什么、还缺少什么。

导出兼顾两种需要：JSON 与 Markdown 用于保真保存和迁移，阅读版优先采用 HTML，提供清楚的日期导航与中文图文排版。AI 可帮助寻找模糊记忆或回顾某个月，但原始记忆优先、AI 输出其次（Original Memory is Primary, AI Output is Secondary），用户始终能够回到原文。

## 为什么做这个项目（Why This Project）

项目有明确的第一位用户和可验证的任务：能否完整保存一批记录、找回指定内容、生成愿意重读的日志。它也提供一条从用户需求到可演示软件的完整实践路径，便于团队分工与评价结果。

隐私融入设计（Privacy-by-design）和非技术用户可用（Non-CS Accessibility）同样是产品目标：基础功能不需要模型服务，不默认发送日记到云端，使用者无需理解 AI 内部机制。

## 有什么不同（What Makes It Different）

重点是已经存在的 Hope 记忆及其完整归档体验：来源适配、原文和图片关联、离线可用、迁移质量与阅读版质量。它不是以生成新日记或聊天为主要入口。

[Witness](https://github.com/SpaseCases/Witness) 与 [Dear Agent](https://github.com/BitmapAsset/dear-agent) 是原材料中的参考项目。我们需要通过实际归档与使用体验证明价值，不能把“增加界面或 AI”本身当成独有创新。

## V1 一句话

交付一个能导入本人授权数据或自有文件、在本地保存原文与日期和图片关联、浏览并按日期筛选、进行中文基础关键词搜索，并导出 JSON、Markdown 与至少一种精美阅读格式的单机归档软件。

Hope 数据接口和权限尚未验证；若无法获得可靠入口，采用自有文件导入，并明确调整后的定位，不把样例演示称为已完成 Hope 自动接入。

## 两个未来想法（Future Ideas）

- **时间胶囊时间线（Time Capsule Timeline）**：连接当时的期待、中间的日记与今天的回应。胶囊数据与状态仍待验证，不提前读取未开放内容。
- **同频者关系章节（Relationship Chapter）**：将用户选择的交流、相关日记和本人反思整理成可编辑的记忆章节。聊天来源与双方隐私需要另行确认。

两者均不属于 V1 基础承诺。
