# 2026-09-08 上推变更记录

比较基线：`f81685c`（原 origin/main）。本记录涵盖此前累计开发、本次统一提交的变化，不仅是最后一轮日历功能。

## 功能变化

1. **CLI/UI 共用完整归档流程**：原 main.py 只下载 raw pages 并合并 JSON；现在与 UI 共用 application.export_archive()，依次下载、标准化、保存媒体、生成 Markdown。没有复制 core 业务逻辑。
2. **新增 Tkinter 桌面界面**：输入本人 ID、日期、日记类型和根目录；后台执行、显示阶段和结果、阻止重复提交、打开输出文件夹。每次创建独立运行目录，失败保留已保存文件。
3. **新增日期选择器**：开始/结束日期并排，日历选择、年月导航、今天按钮、未来日期置灰；默认本月首日至今天。application 独立校验未来日期与起止顺序，CLI 同样生效。
4. **Markdown 阅读体验**：去掉生成的 YAML Front Matter；显示已确认情绪/天气名称；留言显示作者和回复对象，隐藏内部 ID 与时间字段；不再追加重复 Original text 区。源数据仍保留原值。
5. **图片 presentation**：Pillow 只读尺寸/EXIF；单图竖图46%、横图65%、近方形55%、长图38%（高宽比>=2.5，暂定）。两图并排，三图三列，四图2×2；最大高度480px，保留原始媒体与相对路径，不裁切或改写文件。
6. **独立 Markdown 输出位置**：--output-dir 可选择新展示目录，--archive 仍提供媒体和 manifest。
7. **中文学习资料**：中文 README、Notebook 常用命令、application/UI 使用说明和图片规则文档。

## 兼容性与保留范围

- main.py 现在是完整归档入口，--data-dir 为 --output-dir 的别名，表示根目录；每次创建新子目录。
- 旧 --page-size、--timeout、--max-pages CLI 参数不再接受；共享流程沿用 core 默认值。各阶段独立工具仍可用。
- media/Markdown 独立工具要求 normalized document，不能直接传 backend list。
- tkcalendar 依赖 Babel；UI 没有迁移框架。
- 图片布局依赖阅读器支持 inline HTML/CSS；PDF 由用户自己的工具导出。
- api.py、storage.py、normalization.py、normalize.py、media.py 和 references/ 未修改。
- raw/normalized JSON、日记正文、媒体、真实验证输出、个人 ID/凭据不纳入本次提交。
- 相对 Git 基线无 PDF 模块删除：临时 PDF 实验未进入该基线，本次也不包含 PDF 自动导出。
