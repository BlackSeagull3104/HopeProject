# Hope Archive 产品概念与设计

> 状态：产品设计基线，非已实现功能清单。更新日期：2026-09-06。

本文是产品与设计的长期事实基准（Source of Truth），维护项目为什么存在、服务谁以及应遵守的设计原则。版本承诺、里程碑与验收以 [scope.md](scope.md) 为准；首次了解项目请读 [project-introduction.md](project-introduction.md)。新增想法不会因写入本文而自动进入 V1。

项目在仓库中使用 **Hope Archive**；早期材料中的 **Hope Personal Archive** 指同一项目。名称暂定，不表示获得 Hope 官方认可。

## 1. 背景与用户问题

发起者长期在 Hope 写日记，个人估算已积累约 82,000 字，并表示尚未找到满意的批量导出方式。朋友尝试过类似导出，但结构与排版未满足其长期保存需求。这些是需求访谈材料，不是对 Hope 当前产品能力的完整审计，也不是已验证的接口方案。

核心痛点（Problem / Pain Point）是：记录持续积累，却难以完整迁移；正文、日期与图片在粗糙导出中容易脱节；想找回一段经历时需要反复翻阅；即使拿到纯文本，也缺少适合重读的阅读体验。

用户需求因此不是单纯“生成摘要”，而是能够自主保存已经写下的记忆，确认保存了什么、缺少什么，并在未来重新找到和阅读它们。

## 2. 目标用户与价值主张

首要用户是已在 Hope 积累较多日记、希望备份或重读的用户，尤其是不愿配置开发环境或 AI 工具的非计算机专业用户。其他平台用户属于未来扩展对象，当前不承诺多平台适配。

| 典型场景 | 产品应提供的价值 |
| --- | --- |
| 保存过去一年的日记 | 正文、日期和图片关系完整，缺失可见 |
| 找回一次旅行或重要选择 | 按时间浏览，搜索后回到原文 |
| 断网或离开原平台后重读 | 本地档案与图片可独立使用 |
| 制作年度日志 | 同时拥有可迁移数据与精美阅读版 |
| 可选地回顾某个月 | 有来源、可修改的辅助回顾 |

价值主张是数据可携带性（Data Portability）、本地自主保存（Local Ownership）与重新回顾（Revisit）。完整性、阅读质量和低门槛是需要通过用户体验与样本核对证明的目标，尚不是已证实的竞争优势。

## 3. 核心设计原则

### 原始记忆优先，AI 输出其次

**Original Memory is Primary, AI Output is Secondary.** 原文、原始时间和图片是档案主体。AI 生成的索引、摘要与关联是派生数据（Derived Data），可以删除或重建，不能覆盖原文，也不能冒充用户当时的表达。展示标题、模型推断与用户后补反思均应与源内容区分。

### 本地优先（Local-first）

完成导入后，浏览、基础搜索与导出应无需开发者服务器或模型服务。档案使用可迁移格式，媒体保存为本地文件，不依赖长期有效的远程地址。本地优先不自动意味着文件加密或设备安全；具体保护能力应如实说明。

### 隐私融入设计（Privacy-by-design）

仅处理本人获授权访问的数据或用户有权提供的文件，最小化收集和披露。凭据与档案分离，不进入正文、日志或导出；默认无内容遥测与云端 AI 外发。云端能力必须由用户主动启用，并明确发送范围、服务方与成本，不设置静默远程回退。

删除派生数据不影响原文；若支持原文删除，应使相关索引和摘要同步失效，并说明既有导出及备份不会自动删除。静态加密必须一起考虑媒体、索引、密钥与恢复，不能以应用锁代替文件保护。

### 非技术用户可用（Non-CS Accessibility）

用户应通过导入、浏览、搜索和导出完成任务，无需理解 Agent、模型上下文协议（MCP）或向量数据库。界面用可理解的范围、进度、结果位置和失败说明表达状态。安装包是长期易用性目标，课程版本是否需要分发级安装体验由范围文档决定。

## 4. 日记归档总体目标

日记归档（Journal Archive）负责将授权来源转换为可长期使用的个人档案。关键是保存来源语义：保留原文、段落、表情、原始日期与时区信息以及图片顺序；未知字段明确留空，不用导入时间替代写作时间，不补造标题或日期。

档案应区分原始资料、规范化记录、媒体与派生内容。重复导入应可识别已有记录；更新不能静默破坏旧档案。媒体失败应保留关联与缺失说明，不能把远程 URL 当成已经离线保存的图片。

完整性必须相对于可确认的来源范围描述。来源总量未知时，只报告已获取内容与限制，不能宣称“全量完成”。来源接口不可用时，自有文件导入仍能支撑归档产品，但不能据此声称已完成 Hope 自动接入。

## 5. 两层导出

| 层次 | 用途 | 设计方向 |
| --- | --- | --- |
| 保真数据层（Machine-readable Export） | 迁移、备份、后续再处理 | 版本化 JSON、逐篇 Markdown、本地媒体与清单；JSON 承担完整结构，Markdown 保留正文及可表达的元数据 |
| 阅读呈现层（Reading Export） | 重读、分享、年度日志 | 优先 HTML，PDF 为可选增强；中文排版、月份导航、原文与图片、完整性说明 |

两层来自同一档案。阅读版不能替代保真数据包，AI 回顾应单列。导出不带凭据或带认证参数的资源地址；图片与内部导航使用可迁移的本地相对路径，同日多篇不得互相覆盖。

建议阅读版按“封面与覆盖范围 → 年月目录 → 逐篇日记 → 可选回顾 → 缺失与来源说明”组织。优先保证长文、中文与图片可读，再扩展主题样式。用户选择分享范围和敏感字段，不自动公开档案。

## 6. 搜索与摘要方向

### 从中文关键词到混合检索

关键词搜索（Keyword Search）与日期筛选构成基础路径，结果显示日期、命中片段和原文入口。具体中文索引方案需用短词、长词和中英混合查询验证，不能以“建立全文索引”代替可用性判断。

混合检索（Hybrid Search）是后续增强：在同一日期范围内合并关键词与语义检索（Semantic Search）候选，再去重排序。本地嵌入（Embedding）优先，长文片段保留来源定位，索引应可重建。模型、切块长度和排序参数属于实现决策，不在产品文档固定。

检索增强生成（Retrieval-Augmented Generation, RAG）可用于具体问题回答，但少数命中条目不代表某月全部经历。没有证据时应说明未找到，而不是断言某件事从未发生。

### 有覆盖范围和证据的回顾

摘要（Summary）先考虑月度，再考虑层级摘要（Hierarchical Summarization）：原始条目 → 月度回顾 → 年度回顾。先枚举所选时段全部条目，报告实际覆盖与失败部分；重要结论可回到原文，年度概括不能只靠多次压缩后的文本推断。

生成内容标明 AI 来源、范围和时间，区分事实、概括及用户反思。不补写未记录经历，不作人格定论或情绪诊断。原文变化后标记相关摘要过期，用户批注独立保存。模型处理有计算、下载或调用成本，缓存减少重复计算，但不把首次全量处理描述为免费。

## 7. 总体架构

以下是目标职责划分，不表示模块均已实现，也不是 Hope 的实际数据结构（Schema）。仓库当前为 Python 项目骨架；界面及模型技术选型仍待范围冻结。

```text
获允许的 Hope 个人数据来源 / 用户自有文件
                    |
           Connector / File Import
                    |
         Parser + Import Manager
                    |
       Original Store: SQLite + Media
          |                     |
     Browse / Export      Derived Store
                           Index / Summary
                                |
                         Search / Summary
          |                     |
          +------ Local UI -----+
                    |
          Optional Agent Layer

Search / Summary -> Model Adapter
                 -> 本地模型 / 用户主动启用的云服务
```

| 模块 | 边界 |
| --- | --- |
| 数据连接器（Connector）与文件导入 | 隔离来源、认证和格式变化，不决定业务展示 |
| 解析与导入管理 | 保留原始语义，管理去重、写入与结果报告 |
| 原始存储与媒体管理 | 保存正文、关系和实际媒体，明确缺失 |
| 派生存储 | 保存可重建索引、向量及有来源的摘要 |
| 浏览、搜索、摘要、导出服务 | 复用档案能力；模型故障不阻断基础功能 |
| 本地界面与可选 Agent 层 | 调用服务，不扩大数据权限 |

SQLite 与本地媒体文件是建议存储方向。模型适配层（Model Adapter）隔离不同推理服务；网络路径需要明确配置。可靠保存和导出优先于复杂组件数量。

## 8. Hope 接入与负载边界

Hope 应用程序接口（API）、字段结构、认证方式、分页、账号权限、更新或删除标记、图片质量及链接有效期均待验证。朋友转述的权限问题未经审计，不能记为已证实漏洞，更不能成为数据入口。

仅使用正常授权且获允许的通道。不枚举其他用户、不绕过权限，不以观察到请求等同于获得第三方调用许可。无法确认数据归属时暂停处理相关数据。真实增量同步（Incremental Sync）需要可靠更新依据；重复导入去重不等同于增量同步，源端暂未返回一篇日记也不代表应删除本地副本。

内容分发网络（Content Delivery Network, CDN）是否参与 Hope 图片分发、使用哪家服务、如何计费以及实际服务器成本均未知。原文中的成本例子不能用于推算 Hope 账单。设计目标是缓存、减少重复请求、尊重限额和明确失败，而不是隐藏访问行为。低并发单机原型也不能证明大规模推广的总负载可接受。

## 10. 两个进阶方向（Advanced Points）

### 时间胶囊时间线（Time Capsule Timeline）

将埋下时间、计划开启时间、实际开启时间、原文和现在的回应串成“过去的自己 → 中间经历 → 未来的自己”。相关日记为期待与回应提供上下文，AI 只辅助建议关联或起草反思，用户确认优先。

胶囊类型、状态与事件字段能否取得仍待验证。不提前读取平台尚未开放的内容，未开启胶囊只展示获授权可见的信息。此方向不影响基础归档交付。

### 同频者关系章节（Relationship Chapter）

把用户选择的一段有意义交流整理为可编辑章节：自定昵称与时间范围、话题、少量原文入口、同期日记和本人反思。不能因同名或语义相似直接认定人物关系，也不对他人作性格评分。

聊天入口、双方消息完整性与已删除内容的可获取性均未知。双方信息需要额外的使用边界：默认本地处理，云端处理或分享前选择范围并确认授权，脱敏不等于无法再识别。删除章节不应擅自删除同期日记。

## 11. 可选 Agent 层

智能体层（Agent Layer）是成熟服务之上的未来交互方式，可协调搜索、读取、摘要和导出。软件基础链路不依赖 Agent；固定流程足够时不引入自主循环。

Agent 将导入文本视为数据，不执行其中的指令；只能使用受限工具与用户选定的数据范围，默认无外部发送或源平台写回能力。它不能替代账号权限、来源证据或用户对分享的选择。

## 12. 面向 Hope 官方的长期定位

希望成为补充个人数据归档、迁移和长期回顾体验的原型：用户继续在 Hope 留下记忆，Archive 帮助他们在自己设备上保存、查找和重读。合作、官方推荐与用户信任提升都是待验证的长期目标。

后续交流应展示完整流程、归档质量、实际请求量和明确的数据流，并寻求官方导出格式或只读个人数据接口、版本说明、媒体策略与推荐限额。公开演示使用合成或经确认可公开的数据。

课堂原型成功不等于可面向大量真实账号发布。推广前需要重新评估总负载、凭据管理、更新与分发、隐私说明和恢复流程，与官方确认稳定的使用边界。
