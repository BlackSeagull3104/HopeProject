## 2026-10-20 截图反馈复核

复核基线为 `68393aa`，开始时工作树干净。上述七项反馈已有实现，本次未重复修改功能代码。评论资料过滤位于 `privacy.py`，分页响应和合并备份分别通过 `save_raw_response`、`save_diaries` 最小化保存；作者主动写入正文的联系方式不作模式替换。旧备份仍需私人保管，本次未读取或改写真实用户数据。

另一张截图提出安装包过大、可能误打包 NumPy。当前 `packaging/backend.spec` 已明确排除 NumPy、OpenCV、ONNX Runtime 和 RapidOCR；这些依赖由独立 OCR runtime 承载。`ocr_worker.py` 使用 NumPy 将图片转为推理输入，RapidOCR 本身也使用数组计算；`semantic_worker.py` 使用 NumPy 构造 ONNX 输入并归一化向量。因此不能简单删除 NumPy，或只替换应用内几行代码便解除依赖。

本机现有 `src-tauri/binaries/ocr-runtime/_internal` 的未压缩目录测量如下。这是现有运行目录的观察，不是本次重建的安装包，也不能把未压缩大小直接作为安装包可减少的字节数：

| 组件 | MiB |
| --- | ---: |
| OpenCV（cv2） | 111.76 |
| ONNX Runtime | 35.84 |
| RapidOCR（含随包资源） | 30.88 |
| NumPy 动态库（numpy.libs） | 20.18 |
| NumPy 包目录 | 6.07 |

当前证据不支持“NumPy 是无用依赖”或“删掉后一定小于 100 MB”的结论。本次保持离线 OCR 和可选语义检索能力，没有删除二进制、替换推理依赖、重建或覆盖既有安装包。后续若专门进行体积优化，需比较候选运行库的实际压缩产物，并重新验证识别、语义推理和打包应用。
