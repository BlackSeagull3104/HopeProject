# AI 日记助手 v2 开发说明（0.2.0-dev）

## 当前结构

沿用 v1 的规范化 JSON、按用户归档根目录隔离的 SQLite FTS5 索引、BYOK provider adapter 与 Windows 凭据管理器。`ai_assistant.py` 保持问日记行为；`ai_workflows.py` 在本机内存中管理回顾、时间线及已选日记任务。界面仍是单个 AI 日记助手页面。

## 四种模式

- **问日记**：按相关性检索最多 8 个片段。指代“那天/那篇”的追问优先重用上次引用的来源；关键词没有在来源中出现时，先查相同日期，再按原问题做本地宽搜。历史最多 4 条有效消息，引用 ID 最多 8 个。
- **回顾**：用户明确选择日期和回顾视角。综合/生活/自定义视角读取范围内的日记；学习工作和旅行活动视角以公开的字面词表作本地筛选。主题视角用字面提及统计，列出每个主题的支持篇数和可打开日期；提及次数不等于重要性。
- **时间线**：本地检索相关日记后按日期升序分组与合成，不会填补未记录的时间段。当前最多取 50 篇相关日记。
- **已选日记**：本地搜索把稳定来源 ID 交给助手；后端在当前账号索引中重新解析这些 ID，最多 50 篇。模型只见这些条目的片段。

## 分层回顾与预估

普通短日记保持完整；长日记按段落切为最多 3,200 字符的片段。每次模型请求最多 8 个片段、12,000 个正文字符。最多处理 120 篇、160 个片段；超限时要求缩小范围，不静默丢弃。第一层逐组整理；后续每组最多合并 6 个摘要，直到形成最终结果。每层携带原始来源 ID；UI 展示实际来源列表，未知模型引用标记会被移除。单组请求只调用模型一次。

预估显示篇数、片段数和模型请求次数，不假定供应商价格或模型上下文窗口。超过 16 篇或 2 次请求时，需要额外确认。进度按分组更新；取消使后续请求停止，正在等待的非流式请求可能仍会完成，但其迟到结果被丢弃。失败后的重试复用本进程中已完成的分组摘要，不把中间提示写到磁盘。

## 隐私与导出

首次模型调用前说明所选服务商、模型和发送范围。回顾可能把所选日期范围内的所有相关日记分批发送；已选模式不扩展到未选择的日记。任务、会话消息和分组摘要仅保留在当前进程内。开发诊断须设置 `HOPE_AI_DEBUG=1`，打包版不可用，也没有生产 API 或 UI 入口；诊断只返回词项、数量、分数和截断状态，不返回正文或路径。

Markdown 导出写入用户选定的 `<归档根>/archive/AI回顾/`。文档标明是 AI 生成摘要，含生成时间、范围、模型、正文与日期/类型/标题来源列表；不会写入 backup/raw 或 backup/normalized，也不导出密钥、内部来源 ID 或模型提示。导出使用排他写入，避免覆盖。

## 合成语义检索基准

基准仅用临时合成日记，没有真实日记或付费 API 调用。

| 类别 | 示例 | 命中 |
| --- | --- | ---: |
| 精确字面词 | nanoGPT、tokenizer、梵净山 | 3/3 |
| 显式别名 | 自然语言处理→NLP、贵州→梵净山 | 2/2 |
| 无共享词的语义改写 | “训练语言模型”→nanoGPT、“文本编码”→tokenizer、“去过什么山”→梵净山 | 0/3 |

因此 v2 不默认添加 embeddings，也不自动把问题送给模型改写。语义改写确有漏检，但自动云端改写会引入额外请求和隐私选择。后续可在清晰的用户开关下先试只发送问题的可选改写，再用匿名评测决定是否需要本地语义索引。

## 已知限制与后续

当前为非流式 provider 调用。取消不会物理终止已经发出的网络请求。模型仍可能写出未获证据支持的解释，来源列表用于人工核对；系统只能剔除未知引用标记，不能自动证明每句话。主题字面词表和时间线 50 篇上限可能漏检；日期自然语言解析仍需改进。上线前需要人工核查 Windows 安装版的实际布局、交互、无障碍与各 provider 的真实响应。
