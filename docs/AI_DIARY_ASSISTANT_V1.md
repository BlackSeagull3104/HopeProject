# AI 日记助手 v1（0.2.0-dev）

## 目标与边界

该助手回答“我的日记里写过什么”，不是通用聊天机器人。规范化 JSON 仍是唯一数据源；本地 SQLite FTS5 索引可随时重建。检索只读取日记，默认不读取时间胶囊。

首次使用会明确告知用户：问题会先在本机检索，只把最多 8 个相关片段连同当前问题发送给用户选择并已配置的第三方模型。整个归档、内部文件路径、数据库路径和 API Key 都不会进入模型上下文。会话历史仅存在于当前页面内，刷新后清空。

## 数据流

1. 在本机从问题提取少量可解释关键词，并对 NLP、自然语言处理、nanoGPT、梵净山等常见混合写法做确定性扩展。
2. 使用 FTS5 trigram 与短词字面匹配检索，应用日期范围和日记类型筛选。
3. 按词频、标题命中和日期稳定排序；长日记按段落切片。
4. 去重后最多选择 8 个片段，总正文不超过 12,000 字符。
5. 把 grounding contract、最多 4 条有效历史消息、片段和问题发送至选定 BYOK 服务商。
6. 返回回答及稳定来源 ID；点击来源仍由本地详情接口读取，不向前端暴露磁盘路径。

模型调用当前使用非流式响应。这样能复用所有现有 provider adapter，并让失败状态一致；后续版本可在本地传输层具备可靠的取消和断线恢复后加入流式输出。

## 合成检索基准

自动测试只创建临时合成归档，不读取真实用户内容，也不调用任何真实 AI API。基准覆盖：

- 中文、英文和中英混合查询；
- NLP / 自然语言处理、nanoGPT、贵州 / 梵净山别名；
- “我最近学了什么”等自然问法；
- 日期范围与日记类型筛选；
- 长日记切片、上下文上限、来源去重和稳定 ID；
- 无关问题返回证据不足且不调用 provider；
- 模型上下文与安全元数据中不存在归档路径和 API Key。

当前无需 embeddings：上述目标查询可由确定性词法检索稳定命中，结果可解释、离线、无额外模型下载，也没有向 embedding 服务发送文本的隐私面。若未来真实的匿名评测显示语义改写召回不足，再以显式可选、本地优先、可删除的索引形式评估 embeddings。

## 已知限制与 v2 方向

- v1 不推断复杂时间表达；“最近”的精确范围应由日期筛选控制。
- 词法检索对完全无共享词的同义改写能力有限。
- 引用可追溯到日记条目，但当前不会定位到条目内部的精确字符区间。
- 模型仍可能生成不理想的概括；界面会展示实际检索来源，证据为空时不会调用模型。
- v2 可加入用户可见的查询改写、可选本地 embedding、流式取消、片段级高亮和离线质量评测集。
